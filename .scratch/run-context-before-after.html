How configmap passes settings: before and after the run context

Example map: outer has _settings = @{ process = 'steps' }; its step step1 runs qbuild inner; inner is a plain scriptblock with no _settings.

Before

One module variable, scopes stack on top of it

Each entry pushed its _settings onto $script:ConfigMapSettings. A nested qbuild pushed on top of whatever was already there.

After

Each invocation builds its own run context

Settings come from the base settings plus the map, never from the caller. Child contexts are passed down explicitly.

  • Base settings: defaults plus QCONF_*, captured at import (refreshed by Update-ConfigMapSettings).
  • Run context: New-ConfigMapRunContext per qbuild/qrun/qconf call; New-ConfigMapEntryContext derives a child per entry from the base and the map.
  • Discovery cache: settings for a loaded map are base + that map's DiscoveryCache* overrides, so a running entry doesn't affect them either.
