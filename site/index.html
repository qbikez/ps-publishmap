01 Your map file is the CLI.

Write a hashtable in .build.map.ps1. Each key becomes a command, each param() becomes a flag, and each ValidateSet becomes a completion list.

.build.map.ps1
@{
    # Plain script block
    clean = { Remove-Item bin, obj -Recurse -Force }

    build = @{
        description = 'Build the project'
        exec = {
            param([ValidateSet('Debug', 'Release')]$Configuration = 'Debug')
            dotnet build --configuration $Configuration
        }
    }

    deploy = @{
        description = 'Deploy to specified environment'
        exec = {
            param(
                [ValidateSet('dev', 'staging', 'prod')]$Environment = 'dev',
                [switch]$Force,
                [int]$Timeout = 300
            )
            Write-Host "Deploying to $Environment..."
        }
    }
}
what you get
PS> qbuild build -Configuration Release
PS> qbuild deploy -Environment prod -Force -Timeout 600

PS> qbuild <TAB>

PS> qbuild deploy -<TAB>

PS> qbuild deploy -Environment <TAB>

02 What it does

Built on the publishmap module. Runs anywhere PowerShell 7 runs: Windows, macOS and Linux.

Typed parameters

Parameters come straight from your script blocks: types, defaults, switches and ValidateSet.

Tab completion

Entries, nested entries, parameter names and values complete in the shell. ValidateSet('@envs') reads its values from a sibling key, computed only when needed.

Process types

exec scripts, multi-step steps, config options, and bun / npm package scripts in one tool.

Maps that compose

A root map can #include project maps, so one qbuild covers a whole workspace.

Fast listing

Discovery is cached as JSON and refreshed when the map, its includes or its _dependsOn files change.

Starts from your repo

qbuild !init writes a map with defaults for what it finds, including bun or npm when a lock file or package.json is present.

processwhat it runs
execThe entry's exec script block. This is the default.
stepsA multi-step process with persisted state.
optionsConfiguration get, set and show.
bun, npmpackage.json scripts: qbuild web dev -- --watch runs bun run dev --watch in the entry's directory.

03 Switch settings, not files.

Give an entry named presets and a template, and QBuild reads and writes the value for you. Templates exist for appsettings JSON, .env files and dotnet user-secrets. Your own get and set still win when you need them.

.build.map.ps1
@{
    storage = @{
        description = 'Storage endpoint in appsettings JSON'
        _settings   = @{ process = 'options' }
        _template   = 'appsettings:src/appsettings.Development.json'
        options     = @{
            local = @{ 'Storage:BaseUrl' = 'https://127.0.0.1:10000/devstoreaccount1' }
            prod  = @{ 'Storage:BaseUrl' = 'https://prod.example' }
        }
    }
}
usage
PS> qbuild storage

    storage  Storage endpoint in appsettings JSON
    ├─ ● Active  prod
    ├─   Value   {"Storage:BaseUrl":"https://prod.example"}
    └─   Options local, prod

PS> qbuild storage -value local

04 Readable by agents and scripts.

AI agents and automation get a structured catalog instead of scraping help text. Each command reports its name, description and parameters with types, defaults and allowed values.

PS> qbuild !describe                     # all commands as objects
PS> qbuild !describe build               # one command
PS> qbuild !describe | ConvertTo-Json -Depth 6
# Install the shipped agent skills into this project
PS> qbuild !agent.init                    # Cursor
PS> qbuild !agent.init -Agent claude      # Claude Code
PS> qbuild !agent.init -Agent copilot     # GitHub Copilot

05 Start in four lines.

Requires PowerShell 7 or higher.

  1. Install and load the module

    Install-Module configmap
Import-Module configmap

  2. Create a map with defaults for this directory

    qbuild !init

  3. See what you can run

    qbuild

  4. Run a command

    qbuild build -Configuration Release

Add Import-Module configmap to your PowerShell profile so completion is ready in every shell.
