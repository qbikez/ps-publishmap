What changed since run #8

PR #78 (perf suite), on top of PR #79 (Linux dotfile fix) and c250be2 (fewer iterations).

  • Fewer iterations. Scenarios now stop at 10 iterations or an 8 s budget, instead of 30 and 10 s. In this container a suite run dropped from ~77 s to ~50 s, and no scenario in the CI fixtures reaches the budget any more.
  • New module scenario. Import-Module in a fresh pwsh, timed with its allocations: 1 untimed + 10 timed processes, about 7.2 s per run. Median ~242 ms, about 24 MB allocated.
  • new-shell no longer times module loading. Import happens before the timer, and an untimed TAB on a copy of the fixture pays the one-time session warm-up first. The timed TAB is now about 100–140 ms, but each process still takes about 1.3 s of wall time.
  • The per-fixture new-shell: Import-Module rows are gone, replaced by the single module row.
  • Fresh-shell scenarios now dominate. The iteration cut does not apply to them, so module load and new-shell are about half of each run.
  • Dotfile maps work on Linux. PR #79 makes the discovery cache valid there, and the suite's own “touch the map” step now uses Get-Item -Force, so the list and edited scenarios run instead of failing.

How one scenario samples

Measure-Scenario in configmap/test/perf/Invoke-PerfSuite.ps1. This loop runs once per scenario, per side, per round: 3 rounds × base + head = 6 times per job, each time in a fresh pwsh.

while ($times.Count -lt $Iterations -and
       ($times.Count -lt 3 -or $budget.Elapsed.TotalSeconds -lt $ScenarioBudgetSeconds)) { ... }
# stops at 10 samples, or at 8 s once it has at least 3, whichever comes first
1 · Warm-upRuns the action once, untimed. It runs before the budget clock starts and is not a sample.
2 · Timed loopSetup (e.g. touch a map file) → read allocations → stopwatch around the action. Every sample is kept.
3 · Stop10 samples, or at least 3 samples and 8 s elapsed. The budget is wall-clock, so Setup and the allocation reads count against it.
4 · ReportMedian, p95, min and median allocated KB. Compare-Perf takes the median of the 3 per-round medians.
  • Minimum 3 samples. A 5 s call still runs 3 times (~15 s) before the budget can stop it.
  • Budget wins above ~800 ms per call (8 s ÷ 10). In the CI fixtures no scenario is that slow any more, so every scenario stops at 10 iterations.
  • Fresh-shell scenarios are different. They skip this loop and have no budget. module starts 1 untimed + ImportIterations (10) processes. new-shell starts 1 untimed + NewShellIterations (5) processes, and each one runs an untimed warm-up TAB on a copy of the fixture before the timed TAB.
