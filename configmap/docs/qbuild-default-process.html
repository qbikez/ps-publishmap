configmap · qbuild

qbuild is the host and the default handler

The command still loads the map and decides who runs an entry. Running a normal build entry is now a registered handler named qbuild, not a special string compare.

What changed

Before

One function, two jobs

Invoke-QBuild loaded the map and also executed the entry. Anything whose process was not exactly qbuild was assumed to be an external command, so it needed a map file.

  • Dynamic parameters, run, list, and name discovery each checked Process -ne 'qbuild'.
  • QBuild missed the handler and tried to launch a command of that name.
  • An in-memory map could not host another executor.
After

Lookup, then run

A private registry answers “is this process in-process?” Names match ordinal-ignore-case. qbuild is registered when the module loads.

  • A registered name never falls through to the CLI.
  • An empty GetDynamicParam or WriteListEntry keeps the normal qbuild behavior for that slot.
  • Only an unregistered name is handed to qrun or qconf.

Three slots

Each handler can fill run, dynamic parameters, and list. A missing callback is not a CLI handoff.

Invoke

Run

Present: call it and return. Absent on a registered handler: throw. The default calls Invoke-QBuildProcess.

GetDynamicParam

Parameters

Present: call it with the context. Absent: Get-EntryDynamicParam. Unregistered names still use !complete -params.

WriteListEntry

List row

Present: the handler prints the row. Absent: the normal command line. Unregistered names forward list to the external command.

Who owns what

Host · Invoke-QBuild
  • Command parameters, the qbuild alias, and the default map path.
  • Import, assert, and merge the map.
  • Internal commands and the missing-map message.
  • Read _settings.process and build one context object.
  • Completion: internal names, map entries, and !complete for external processes.
  • The external protocol: splat, _sourceFile error, and the recursion guard.
Default handler · Invoke-QBuildProcess
  • Find targets with Get-MapEntries.
  • Filter bound parameters. ProcessAction, ProcessValue, and remaining arguments become passthrough.
  • Run the InvokeQBuildTargets plugin hook.
  • Prompt when a parent entry has no exec.
  • Call Invoke-EntryWrapper.
  • Dynamic parameters come from Get-QBuildProcessDynamicParam. WriteListEntry is left empty.

Same command, four outcomes

build = { ... }qbuild

No _settings.process. Settings default to qbuild. The registered handler runs exec.

process = 'QBuild'qbuild

Lookup is ignore-case, so this is the same handler as the implicit default.

process = 'qprobe'in-process

A test can register qprobe. An in-memory map runs that handler and does not run exec. No _sourceFile is required.

process = 'qrun'external

Not registered. qbuild calls qrun -map <file>. Without a source file this still throws. qconf works the same way, including ProcessAction and ProcessValue.

Where the guard sits

If qbuild is unregistered, the process name still defaults to qbuild, and that command is Invoke-QBuild. Handing off would call the host again. Dynamic parameters, !complete, and the CLI runner all stop when the resolved command is the host. Run throws “no in-process handler is registered.”

Private registry: Register-ConfigMapProcess, Get-ConfigMapProcessHandler, Unregister-ConfigMapProcess. These stay off the public command list. Pull request #34.
